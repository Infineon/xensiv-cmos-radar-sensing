C-Wrapper API

Overview

The pipeline wrapper provides a simple C API for processing radar frames. It abstracts the complex processing pipeline into three main functions: getting the default configuration, initializing the pipeline, and processing frames.

Note

The structures ifx_var_config_t and ifx_result_t contain algorithm-specific data and should be accessed and modified through the usecase high-level API.

Example

The following pseudo-code shows how to use the wrapper API:

/* Get default configuration */
ifx_var_config_t config;
if (pipeline_get_default_config(&config) != 0) {
    /* handle error */
}

/* Optional: override individual fields before init, e.g. mounting */
config.radar_mount_config.mounting_height_m = 2.4f;
config.radar_mount_config.tilt_angle_deg    = 15.0f;

/* Initialize the pipeline */
if (pipeline_init(&config) != 0) {
    /* handle error */
}

for (;;) {
    /* Wait for new radar frame */
    const uint16_t* radar_frame = ...; /* 3264 uint16 values */

    /* Process the frame */
    ifx_result_t result;
    if (pipeline_process(radar_frame, &result) != 0) {
        /* handle error */
    }

    /* Use the result */
    /* result contains the processed output */
}

Configuration

int pipeline_get_default_config(ifx_var_config_t *config)

Get default configuration.

Fills the provided config structure with default values

Parameters:

config – Configuration structure to fill

Returns:

0 on success, non-zero on error

Initialization

int pipeline_init(const ifx_var_config_t *config)

Configure and initialize the processing pipeline.

Must be called before any processing

Parameters:

config – Configuration structure

Returns:

0 on success, non-zero on error

Processing

int pipeline_process(const uint16_t *radar_frame, ifx_result_t *output)

Process a radar frame using stateful wrapper API.

Parameters:

  • radar_frame – Input radar frame data (3264 uint16 values)

  • output – Output structure (will be filled by this function)

Returns:

0 on success, non-zero on error

Algorithm configuration

The Presence Detection and Tracking (PDT) algorithm exposes a small number of parameters that can be adjusted by the integrator according to the use case and deployment environment. These parameters are members of the C struct ifx_var_config_t and are populated with defaults by pipeline_get_default_config(). The most commonly tuned fields are:

  • Mounting parameters — radar_mount_config.mounting_height_m and radar_mount_config.tilt_angle_deg.

  • Field of view — fov_config.min_max_ground_range and fov_config.min_max_azimuth to restrict the algorithm to the relevant region.

  • Radar TX orientation — radar_mount_config.orientation_tx (default 0 = TopLeft; other values are BottomLeft = 1, TopRight = 2, BottomRight = 3).

The default values are defined in the generated file def_var_config_default.c and copied into the user-supplied struct by pipeline_get_default_config(). For most integrations these fields should be overridden at runtime after calling pipeline_get_default_config() and before pipeline_init(), rather than by editing the generated source (which is overwritten on every build).

Calibration matrix update

Imperfections in the transmitter (TX) to receiver (RX) path on the antenna side — especially for antenna-in-package designs — have a non-negligible impact on the phase information. Reflections from very short distances such as housings or radar covers also alter the phase. To compensate, a calibration matrix must be applied prior to the angle calculation.

The calibration parameters are hardware-specific. When the radar sensor is used in a new housing, or when the antenna stack-up changes, the calibration parameters may need to be updated. In such cases please contact Infineon support to obtain an updated calibration matrix.

The PDT algorithm uses one calibration matrix per plane:

  • calib_mat.E — 3×3 complex matrix for the E-plane

  • calib_mat.H — 3×3 complex matrix for the H-plane

Each matrix is stored as a flat array of 9 complex entries (creal32_T[9]) in row-major order. Each complex number is represented as two float values (.re followed by .im).

The calibration values are part of the default configuration generated into def_var_config_default.c. To bake new calibration values into the build, update the initializer of the calib_mat member of the var_config_default struct as shown below (indices Eij / Hij use 1-based row/column to match common conventions):

.calib_mat = {
    .E = {
        { (float)1,          (float)0           },   /* E11 */
        { (float)0,          (float)0           },   /* E12 */
        { (float)0.026344,   (float)-0.0090608  },   /* E13 */
        { (float)0,          (float)0           },   /* E21 */
        { (float)1,          (float)0           },   /* E22 */
        { (float)0,          (float)0           },   /* E23 */
        { (float)0,          (float)0           },   /* E31 */
        { (float)0,          (float)0           },   /* E32 */
        { (float)-0.52022,   (float)-0.84373    },   /* E33 */
    },
    .H = {
        { (float)1,          (float)0           },   /* H11 */
        { (float)0.12753,    (float)0.18146     },   /* H12 */
        { (float)0,          (float)0           },   /* H13 */
        { (float)0,          (float)0           },   /* H21 */
        { (float)-0.89418,   (float)0.29112     },   /* H22 */
        { (float)0,          (float)0           },   /* H23 */
        { (float)0,          (float)0           },   /* H31 */
        { (float)0,          (float)0           },   /* H32 */
        { (float)1,          (float)0           },   /* H33 */
    },
},

Alternatively, the matrix can be overridden at runtime after pipeline_get_default_config() and before pipeline_init():

ifx_var_config_t config;
pipeline_get_default_config(&config);

/* Overwrite E13 with new calibration values */
config.calib_mat.E[2].re = 0.026344f;
config.calib_mat.E[2].im = -0.0090608f;

pipeline_init(&config);
